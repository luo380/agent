## 一、当前同步流程的 5 个致命问题

现在用户上传一个 100 页 PDF 会发生什么？

```
用户点击上传 ── HTTP POST ──▶ FastAPI 工作线程
                                │
                                ├─ 1. 磁盘落盘           (1秒)
                                ├─ 2. 解析 PDF           (5~15秒)
                                ├─ 3. 分块               (2秒)
                                ├─ 4. Embedding 500条    (20秒, 偶发超时无重试)
                                ├─ 5. 写 DB              (1秒)
                                └─ 6. 重建 FAISS 索引    (3~60秒)
                                │
                                ◀── HTTP 返回 ── 用户等了 47~95+ 秒
```

| # | 问题 | 后果 |
|---|------|------|
| 1 | 同步阻塞 HTTP 线程 | 用户界面卡死；FastAPI Worker 被占满影响其他人 |
| 2 | Embedding/解析无重试 | API 抖动 5% 概率超时，整个导入全失败，用户只能重传 |
| 3 | 状态机太粗（只有5种） | 失败了不知道是解析/分块/向量化/索引哪一步挂的，排障全靠猜 |
| 4 | 失败全量回滚 | 前 499 条成功，第 500 条挂 → 前 499 条变成孤儿脏数据 |
| 5 | 无 MD5 去重 | 相同 PDF 改文件名传 10 次 = 解析 10 次 = 检索重复 10 次 |

## 二、状态机细化（5 个 → 12 个状态）

```
uploaded → parsing → parse_error ❌（失败可重试）
                  ↘ parsed → chunking → chunk_error ❌
                                        ↘ chunked → embedding → embed_error ❌
                                                                 ↘ embedded → indexing → index_error ❌
                                                                                                 ↘ ready ✅
```

## 三、失败记录表（单条 chunk 粒度）

新建 `KnowledgeChunkFailures` 表：

```python
class KnowledgeChunkFailures(Base, TimestampMixin):
    """
    单条 chunk 级别失败记录
    场景：500条chunk里前499条embedding成功，第500条超过重试上限
         → 文档状态 embed_error
         → 用户点击「重试失败的chunk」时，只重试这1条，不跑前面499条
    """
    __tablename__ = "knowledge_chunk_failures"

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True)
    user_id: Mapped[int] = mapped_column(BigInteger, ForeignKey("users.id"), index=True)
    document_id: Mapped[int] = mapped_column(BigInteger, ForeignKey("knowledge_documents.id", ondelete="CASCADE"), index=True)

    # chunk 在分块列表中的索引（0-based），因为还没写入数据库没有 chunk_id
    chunk_index: Mapped[int] = mapped_column(Integer, nullable=False)
    # 前 200 字预览（人工排障用）
    chunk_preview: Mapped[str] = mapped_column(String(500), default="")

    # 失败阶段：parse / chunk / embed / index
    stage: Mapped[str] = mapped_column(String(20), nullable=False, index=True)
    retry_count: Mapped[int] = mapped_column(SmallInteger, default=0)
    error_message: Mapped[str] = mapped_column(Text, nullable=False)
```

## 四、异步导入改造（核心）

### 4.1 上传接口立刻返回，后台异步处理

```python
# api/routes/knowledge.py
from fastapi import BackgroundTasks

@router.post("/upload", summary="上传文件到知识库")
async def upload_knowledge_file(
    file: UploadFile = File(...),
    db: Session = Depends(get_db),
    current_user: Users = Depends(get_current_active_user),
    background_tasks: BackgroundTasks,  # 【关键】拿到 FastAPI 后台任务容器
):
    # ========== Step 1：文件落盘（同步做，保证拿到 file_path 和 file_md5）==========
    saved_path = _save_upload_file(file)
    file_md5 = _calc_file_md5(saved_path)
    file_ext = _file_ext(file.filename)

    # ========== MD5 去重：同用户相同内容只解析一次 ==========
    exist = db.query(KnowledgeDocuments).filter(
        KnowledgeDocuments.user_id == current_user.id,
        KnowledgeDocuments.file_md5 == file_md5,
        KnowledgeDocuments.status != DOC_STATUS_PARSE_ERROR,
    ).first()
    if exist:
        return {
            "code": 0,
            "message": "检测到相同内容，已直接复用已有文档",
            "data": {"document_id": exist.id, "reused": True},
        }

    # ========== 创建文档记录 ==========
    doc = KnowledgeDocuments(
        user_id=current_user.id,
        filename=file.filename,
        file_path=saved_path,
        file_type=file_ext,
        file_size=len(open(saved_path,'rb').read()),
        file_md5=file_md5,
        status=DOC_STATUS_UPLOADED,
        progress=1,  # 1% = 文件落盘完成
    )
    db.add(doc)
    db.commit()
    db.refresh(doc)

    # ========== 【核心改动】把 2~6 步扔给后台线程 ==========
    # 注意：不传 db session 本身（非线程安全），而是传 sessionmaker 工厂函数
    from core.db.session import SessionLocal
    background_tasks.add_task(
        _process_document_async,
        document_id=doc.id,
        user_id=current_user.id,
        db_session_factory=SessionLocal,
    )

    # ========== 立刻返回！不等后台跑完 ==========
    return {
        "code": 0,
        "message": "文件上传成功，正在后台解析中",
        "data": {
            "document_id": doc.id,
            "status": doc.status,
            "progress": doc.progress,
            "_poll_url": f"/api/knowledge/documents/{doc.id}/status",
        }
    }
```

### 4.2 后台任务主流程 `_process_document_async`

```python
# api/routes/knowledge.py（或者单独放一个 core/service/document_pipeline.py）
import logging
import traceback
from sqlalchemy.orm import Session
from core.service import knowledge_service, vector_index, document_parser
from core.config import settings

logger = logging.getLogger(__name__)


async def _process_document_async(document_id: int, user_id: int, db_session_factory):
    """
    文档异步处理主流程
    关键：每一步都 UPDATE status + progress（前端可轮询）；每一步都 try/except（失败回滚局部状态）
    """
    session: Session = db_session_factory()
    try:
        # ========== Step 2：解析（5%→25%）==========
        _update_status(session, document_id, DOC_STATUS_PARSING, progress=5)
        doc = session.get(KnowledgeDocuments, document_id)
        try:
            text, parse_meta = document_parser.parse_detailed(doc.file_path, doc.file_type)
            if parse_meta.get("is_scanned"):
                logger.warning("文档 %d 疑似扫描件，当前未开OCR可能解析为空", document_id)
            if len(text.strip()) < 200:
                raise Exception("解析后全文不足200字，疑似扫描件未OCR或PDF内容为空")
            _update_status(session, document_id, DOC_STATUS_PARSED, progress=25)
        except Exception as e:
            return _fail(session, document_id, DOC_STATUS_PARSE_ERROR, e, traceback.format_exc())

        # ========== Step 3：分块（25%→50%）==========
        _update_status(session, document_id, DOC_STATUS_CHUNKING, progress=30)
        try:
            chunks, titles, chunk_metas = knowledge_service.chunker.chunk_document(
                document_id=document_id,
                raw_text=text,
                file_type=doc.file_type,
                file_name=doc.filename,
                parse_pages=parse_meta.get("pages"),
                use_semantic_chunking=settings.ENABLE_SEMANTIC_CHUNKING,
            )
            if not chunks:
                raise Exception("分块得到0条结果，请检查文档内容")
            _update_status(session, document_id, DOC_STATUS_CHUNKED, progress=50)
        except Exception as e:
            return _fail(session, document_id, DOC_STATUS_CHUNK_ERROR, e, traceback.format_exc())

        # ========== Step 4：Embedding 批量向量化（50%→90%）==========
        _update_status(session, document_id, DOC_STATUS_EMBEDDING, progress=55)
        try:
            embeddings, failed_indexes = _batch_embed_with_retry(
                chunks,
                on_progress=lambda done, total: _update_progress(
                    session, document_id, 55 + int(35 * done / total)
                ),
            )
            if failed_indexes:
                # 记录单条失败到失败表
                for idx in failed_indexes:
                    session.add(KnowledgeChunkFailures(
                        user_id=user_id,
                        document_id=document_id,
                        chunk_index=idx,
                        chunk_preview=chunks[idx][:200],
                        stage="embed",
                        retry_count=3,
                        error_message="Embedding API 超过最大重试次数仍失败",
                    ))
                session.commit()
                return _fail(session, document_id, DOC_STATUS_EMBED_ERROR,
                             Exception(f"{len(failed_indexes)}条chunk向量化失败"), "")
            _update_status(session, document_id, DOC_STATUS_EMBEDDED, progress=90)
        except Exception as e:
            return _fail(session, document_id, DOC_STATUS_EMBED_ERROR, e, traceback.format_exc())

        # ========== Step 5：写 chunk 到数据库（90%→95%）==========
        knowledge_service._write_chunks_to_db(session, document_id, chunks, titles, chunk_metas, embeddings)

        # 如果是"重新上传同名文档"，软删除旧版本（增量更新）
        _soft_delete_old_versions(session, user_id, doc.filename, keep_document_id=document_id)

        # ========== Step 6：重建用户 FAISS 索引（95%→100%）==========
        _update_status(session, document_id, DOC_STATUS_INDEXING, progress=95)
        try:
            vector_index.rebuild_user_faiss_index(session, user_id)
        except Exception as e:
            return _fail(session, document_id, DOC_STATUS_INDEX_ERROR, e, traceback.format_exc())

        # ========== 全部完成！撒花 🎉 ==========
        _update_status(session, document_id, DOC_STATUS_READY, progress=100, last_error=None)

    finally:
        session.close()
```

### 4.3 Embedding 带指数退避重试（核心）

```python
import httpx
from tenacity import retry, stop_after_attempt, wait_exponential, retry_if_exception_type
from core.service import embedding_service

EMBED_MAX_RETRY = 3  # 单批/单条最多重试3次，间隔 1s → 2s → 4s

@retry(
    stop=stop_after_attempt(EMBED_MAX_RETRY),
    wait=wait_exponential(multiplier=1, min=1, max=10),
    retry=retry_if_exception_type((
        httpx.ConnectTimeout,
        httpx.ReadTimeout,
        httpx.HTTPStatusError,   # 500/502/503 服务端错才重试
        ConnectionError,
    )),
)
def _embed_one_batch(batch_texts: list[str]):
    """单批 embedding（tenacity 重试装饰器）"""
    return embedding_service.batch_embed(batch_texts)


def _batch_embed_with_retry(chunks, on_progress=None, batch_size=16):
    """
    批量向量化策略：
        1. 16条/批整体重试（99%场景一次就过）
        2. 某批超过重试还挂 → 降级为逐条重试（单条失败不影响同批其他）
        3. 单条还挂 → 记进 failed_indexes，不阻断整体
    """
    total = len(chunks)
    embeddings = [None] * total
    failed_indexes = []
    done = 0

    for start in range(0, total, batch_size):
        end = min(start + batch_size, total)
        batch = chunks[start:end]
        try:
            batch_embs = _embed_one_batch(batch)
            for i in range(len(batch)):
                embeddings[start + i] = batch_embs[i]
            done = end
        except Exception:
            # 批量重试全挂 → 逐条降级
            for j in range(len(batch)):
                gidx = start + j
                try:
                    one = _embed_one_batch([batch[j]])
                    embeddings[gidx] = one[0]
                except Exception:
                    failed_indexes.append(gidx)
                done = gidx + 1
        if on_progress:
            on_progress(done, total)

    return embeddings, failed_indexes
```

### 4.4 工具函数 + 进度轮询接口

```python
def _update_status(session, document_id, status, progress=None, last_error=...):
    doc = session.get(KnowledgeDocuments, document_id)
    if not doc:
        return
    doc.status = status
    if progress is not None:
        doc.progress = progress
    if last_error is not ...:
        doc.last_error = last_error
    session.commit()


def _fail(session, document_id, error_status, exc, tb_str):
    friendly = f"{type(exc).__name__}: {exc}"  # 给用户看的
    logger.error("文档%d导入失败: %s\n%s", document_id, friendly, tb_str)  # 打完整堆栈给开发者
    _update_status(session, document_id, error_status, last_error=friendly)


def _calc_file_md5(file_path: str, chunk_size=8192) -> str:
    """流式计算 MD5（大文件不用全读进内存）"""
    import hashlib
    md5 = hashlib.md5()
    with open(file_path, "rb") as f:
        while True:
            chunk = f.read(chunk_size)
            if not chunk:
                break
            md5.update(chunk)
    return md5.hexdigest()


def _soft_delete_old_versions(session, user_id, filename, keep_document_id):
    """重新上传同名文件时，旧的软删除（避免检索重复内容）"""
    old_docs = session.query(KnowledgeDocuments).filter(
        KnowledgeDocuments.user_id == user_id,
        KnowledgeDocuments.filename == filename,
        KnowledgeDocuments.id != keep_document_id,
        KnowledgeDocuments.status != DOC_STATUS_DELETED,
    ).all()
    for old in old_docs:
        old.status = DOC_STATUS_DELETED
        old.is_deleted = True
    if old_docs:
        # 对应 chunk 也软删除，检索会被 WHERE 过滤掉
        old_ids = [o.id for o in old_docs]
        session.query(KnowledgeChunks).filter(
            KnowledgeChunks.document_id.in_(old_ids)
        ).update({KnowledgeChunks.is_deleted: True}, synchronize_session=False)
    session.commit()


# ========== 新增 API：前端每 1~2 秒轮询一次进度 ==========
@router.get("/documents/{document_id}/status", summary="查询文档导入进度")
def get_document_status(
    document_id: int,
    db: Session = Depends(get_db),
    current_user: Users = Depends(get_current_active_user),
):
    doc = db.get(KnowledgeDocuments, document_id)
    if not doc or doc.user_id != current_user.id:
        raise HTTPException(404, "文档不存在")

    failures = []
    if doc.status in (DOC_STATUS_EMBED_ERROR, DOC_STATUS_CHUNK_ERROR):
        failures = (
            db.query(KnowledgeChunkFailures)
            .filter(KnowledgeChunkFailures.document_id == document_id)
            .order_by(KnowledgeChunkFailures.chunk_index)
            .all()
        )

    return {
        "code": 0,
        "data": {
            "document_id": doc.id,
            "filename": doc.filename,
            "status": doc.status,
            "progress": doc.progress,
            "last_error": doc.last_error,
            "failures": [
                {
                    "chunk_index": f.chunk_index,
                    "preview": f.chunk_preview,
                    "stage": f.stage,
                    "retry_count": f.retry_count,
                    "error_message": f.error_message,
                }
                for f in failures
            ],
        }
    }
```

## 五、集成测试验证清单

| 测试场景 | 期望结果 |
|---------|---------|
| 正常 100 页 PDF | 上传接口 1 秒内返回；前端轮询 1→25→50→90→95→100；最终 status=ready |
| Embedding 偶发超时（5%概率） | tenacity 重试 3 次（1s→2s→4s）后恢复，文档最终 status=ready |
| Embedding 全挂（API挂10分钟） | 超过重试上限后文档状态 embed_error；失败 chunk 记录进失败表 |
| 用户上传过程中刷新文档列表 | 列表显示 status（parsing/chunking...）+ progress 进度条在动 |
| 同一个 PDF 改名传 3 次 | 第 1 次正常处理；第 2/3 次立刻返回 reused=True，不重复解析不重复写chunk |
| 传 V2 替换同名 V1 | V1 软删除（status=deleted），检索结果只出现 V2 内容，不重复 |

## 六、关键注意点

1. **BackgroundTasks 的局限**：FastAPI 自带的后台任务和进程绑定，进程死了任务就丢。如果严格要求「服务器重启也能继续未完成的文档」，要升级 Celery + Redis（消息队列持久化），但架构复杂度翻倍。先用 BackgroundTasks 跑，真遇到重启丢任务再切。
2. **Session 不能跨线程传**：主请求的 SQLAlchemy Session 非线程安全，绝对不能直接传给后台任务。必须传 `SessionLocal`（sessionmaker 工厂），后台任务里自己 `factory()` 开新 session，用完 `.close()`。
3. **错误信息分两档**：给用户看的 `last_error` 写友好中文（「调用嵌入接口超时，请稍后点重试按钮」）；完整堆栈只打日志，不给前端。
4. **进度档够用就好**：5/25/50/90/95/100 这 6 档就够，不用精确到 embedding 的 87% 这种，用户感知不大。
5. **重试只对临时错误生效**：tenacity 的 `retry_if_exception_type` 只包网络超时/5xx，不要对 400 Bad Request（比如用户内容超长）重试，重试 100 次也过不了还浪费钱。
