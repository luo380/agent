## 三、推荐执行顺序（优先级重排）

```
现在（第一周）：
  1. 先做 缺口7 评测体系（轻量版，1天能搭好基础框架）
     → 因为后面所有缺口的"对比实验"都依赖它
  2. 再做 缺口2 Metadata Filtering（2~3天）
     → 现在的过滤能力太弱，用户用起来痛点明显

     → 表格抽取能立刻改善"答案里出现乱线"的体验

第二周：
  4. 缺口6 知识库工程化（3~5天，工作量最大的一个）
     → 异步上传 + 状态机细化 + 重试机制
     → 这是"从玩具变产品"的关键一步

第三周以后：
  5. 缺口5 的 PaddleOCR + 缺口6 的 MD5去重/增量更新
  6. 缺口8 pgvector（等 FAISS 文件真的不够用了再上）
```
